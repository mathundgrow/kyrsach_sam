# Code Graph Analyzer — как работает весь проект

Документ описывает архитектуру, все основные функции и полный путь данных:
от выбора папки с проектом до графа, аналитики, советов ИИ-помощника и экспорта отчёта.

---

## 1. Что делает приложение

**Code Graph Analyzer (Графовый ИИ Анализатор)** — десктопное приложение на Flutter,
которое статически анализирует исходный код проекта на **Dart**, **Python** и **C#**:

1. Пользователь выбирает папку проекта.
2. Приложение рекурсивно находит файлы `.dart`, `.py`, `.cs`.
3. Каждый файл разбирается своим парсером (паттерн «Стратегия»).
4. Находится два типа сущностей:
   - **классы** (`ClassNode`);
   - **связи между классами** (`ClassRelation`) — наследование и использование.
5. Строится интерактивный граф зависимостей.
6. Считаются архитектурные показатели:
   - аномалии «God Object»;
   - изолированные классы;
   - оценка здоровья проекта (Health Score).
7. Строится структура наследования:
   - абстрактные классы и интерфейсы определяются автоматически;
   - на графе классы разложены секциями по типу: аномалии, абстракции, обычные;
   - вкладка «Структура» показывает дерево наследования и количество реализаций.
8. Пользователь может:
   - переключаться между графом, структурой, списком файлов, отчётом о здоровье и аномалиями;
   - скрывать изолированные классы;
   - кликать по классам и связям;
   - получать совет локального «ИИ-помощника»;
   - отмечать аномалию как допустимую («так и задумано»);
   - экспортировать отчёт в `.txt`.
9. История открытых проектов хранится локально в `shared_preferences`.
   В истории сохраняется **только путь** к папке: при каждом открытии проект
   сканируется заново, графы и результаты анализа не кэшируются.

Базы данных нет — всё состояние живёт в памяти во время анализа, история проектов
и исключённые аномалии сохраняются в локальном хранилище.

## 4. Архитектура: как работает BLoC

Проект строго следует паттерну **BLoC (Business Logic Component)**.

```
Пользователь
    │
    ▼
Событие (Event)  ──────────────►  ProjectBloc  ──────────────►  Состояние (State)
    │                              (вся логика)                       │
    │                                                                 ▼
    └──────────────────────── BlocBuilder в UI ◄──────────────────────┘
```

- **Виджеты не считают аналитику.** Они только показывают готовые данные из состояния
  и отправляют события в BLoC.
- **Вся фильтрация, расчёты, тексты советов и отчёт** находятся в `ProjectLoaded`
  и `ProjectBloc` (`lib/blocs/project_bloc.dart`).
- UI перестраивается через `BlocBuilder<ProjectBloc, ProjectState>`.

### 4.1. События

| Событие | Поля | Когда отправляется | Что делает BLoC |
|---|---|---|---|
| `AnalyzeProject` | `path` | При открытии экрана анализа | Сканирует проект, считает аномалии/изолированные/здоровье, публикует `ProjectLoaded` |
| `SelectNode` | `node` (может быть `null`) | Клик по узлу графа, по связи в правой панели, по аномалии | Меняет `selectedNode` (или сбрасывает выбор) |
| `SelectSection` | `section` | Клик по пункту левой навигации | Меняет активный раздел центральной панели |
| `ToggleHideIsolated` | — | Переключатель «Скрывать изолированные» | Инвертирует `hideIsolated` |
| `ToggleAnomalyIgnored` | `node` | Кнопка «Не аномалия» / «Вернуть» | Переключает класс в наборе исключённых аномалий, сохраняет решение в `shared_preferences` и пересчитывает здоровье |

### 4.2. Состояния

| Состояние | Что означает |
|---|---|
| `ProjectInitial` | Начальное состояние |
| `ProjectLoading` | Идёт сканирование (показываются спиннеры) |
| `ProjectError` | Ошибка сканирования, хранит текст ошибки |
| `ProjectLoaded` | Успешный анализ: все данные и настройки UI |

### 4.3. Поля `ProjectLoaded`

| Поле | Тип | Назначение |
|---|---|---|
| `nodes` | `List<ClassNode>` | Все найденные классы |
| `relations` | `List<ClassRelation>` | Все связи |
| `filesCount` | `int` | Сколько файлов было просканировано |
| `selectedNode` | `ClassNode?` | Выбранный класс |
| `allAnomalyNodeIds` | `Set<String>` | Все найденные аномалии до решения пользователя |
| `ignoredAnomalyIds` | `Set<String>` | Аномалии, которые пользователь отметил как допустимые |
| `anomalyNodeIds` | `Set<String>` | Активные аномалии: `allAnomalyNodeIds - ignoredAnomalyIds` |
| `isolatedNodeIds` | `Set<String>` | ID классов без связей |
| `healthScore` | `int` | Оценка здоровья 0–100 |
| `section` | `AnalysisSection` | Активная вкладка (`graph`, `structure`, `files`, `health`, `anomalies`) |
| `hideIsolated` | `bool` | Включён ли фильтр изолированных классов |
| `filesQuery` | `String` | Поисковый запрос на вкладке «Файлы» |

### 4.4. Готовые вычисления внутри `ProjectLoaded`

Вся логика вынесена в состояние, поэтому виджеты остаются «тонкими»:

| Метод / геттер | Что возвращает |
|---|---|
| `classesByFile` | `Map<String, List<ClassNode>>` — классы, сгруппированные по пути к файлу |
| `filteredClassesByFile` | То же, но с учётом поиска `filesQuery` только по имени файла |
| `anomalyNodes` | Список активных классов-аномалий |
| `ignoredAnomalyNodes` | Список аномалий, исключённых пользователем |
| `abstractClasses` | Все абстрактные классы и интерфейсы |
| `isolatedNodes` | Список изолированных классов |
| `incomingCount(id)` | Сколько **разных** классов используют этот класс (`usage`) |
| `inheritanceParentIds` | `Map<String, String>` — ребёнок → первый родитель |
| `inheritanceChildren` | `Map<String, List<ClassNode>>` — родитель → дети |
| `parentOf(id)` / `childrenCount(id)` | Родитель класса / количество прямых наследников |
| `hierarchyGroups` | Деревья наследования (`HierarchyGroup` с глубиной каждого класса) |
| `standaloneClasses` | Классы, не попавшие ни в одно дерево наследования |
| `anomalyPenalty` | Штраф за аномалии: `min(anomalyNodeIds.length * 5, 35)` |
| `isolatedPenalty` | Штраф за изолированные: доля изолированных × 20 (не больше 20) |
| `graphNodes` | Список узлов для графа с учётом фильтра изолированных |
| `aiAdviceFor(node)` | Текст совета ИИ-помощника для класса |
| `buildTextReport(projectName)` | Полный текст отчёта для экспорта |
| `copyWith(...)` | Создаёт копию состояния с изменёнными полями (используется событиями) |

> `copyWith` нужен, чтобы не перечислять вручную все 9 полей при каждом событии
> и не потерять, например, `healthScore` при выборе узла.

## 5. Модели данных

### 5.1. `ClassNode` (`lib/models/class_node.dart`)

| Поле | Описание |
|---|---|
| `id` | Уникальный ID. Формат: `путь_к_файлу:ИмяКласса` |
| `name` | Имя класса |
| `filePath` | Полный путь к файлу |
| `line` | Номер строки объявления класса (для перехода в VS Code) |
| `language` | `Dart`, `Python` или `C#` |
| `isAbstract` | `true`, если это абстрактный класс или интерфейс |

### 5.2. `ClassRelation` (`lib/models/class_relation.dart`)

| Поле | Описание |
|---|---|
| `fromClassId` | Кто использует / кто наследует |
| `toClassId` | Кого используют / кого наследуют |
| `type` | `inheritance` (наследование) или `usage` (использование) |

### 5.3. `RecentProject` (`lib/models/recent_project.dart`)

| Поле | Описание |
|---|---|
| `path` | Полный путь к папке проекта |

Имя проекта (`name`) вычисляется из пути через `path.basename`, отдельно не хранится.
В истории **нет** классов, связей, графов или результатов анализа — только путь.
При каждом открытии проекта запускается новое сканирование.

Умеет превращаться в JSON (`toJson`) и восстанавливаться из JSON (`fromJson`) —
это нужно для сохранения истории в `shared_preferences`.
Старый формат (с `name` и `lastOpened`) читается корректно: используется только `path`.

## 6. Сканирование проекта (`ProjectScanner`)

Файл: `lib/services/project_scanner.dart`.

### 6.1. Общий конвейер

```
Папка проекта
   │
   ├─ рекурсивный обход (Directory.list)
   ├─ игнор мусорных папок
   ├─ игнор файлов > 1 МБ
   ├─ выбор парсера по расширению
   │
   ├─ ПРОХОД 1: extractClasses()  → все ClassNode
   ├─ словарь: имя класса → ID
   │
   ├─ ПРОХОД 2: extractRelations() → связи
   ├─ замена имени цели на реальный ID
   ├─ удаление дубликатов узлов по ID
   │
   ▼
(List<ClassNode>, List<ClassRelation>, filesCount)
```

### 6.2. Какие папки игнорируются

```
.venv, venv, node_modules, .git, build, __pycache__
```

Проверка идёт по вхождению `/<имя>/` или `\<имя>\` в путь.

### 6.3. Почему два прохода

В первом проходе приложение ещё не знает, какие классы существуют во **всём** проекте.
Во втором проходе парсер получает `knownClassNames` и может отличить реальную связь
от случайного слова (например, `System.String` или названия из внешних библиотек).

### 6.4. Связывание по имени

Создаётся словарь:

```dart
classIdMap[имяКласса] = idКласса;
```

Парсеры во втором проходе возвращают в `toClassId` **имя** целевого класса.
Сканер заменяет его на настоящий ID через `classIdMap`.

> Ограничение: если в проекте два класса с одинаковым именем в разных файлах,
> словарь оставит только один ID (последний обработанный). Это сознательное
> упрощение для курсового проекта.

### 6.5. Выполнение в изоляте

В `lib/blocs/project_bloc.dart` сканирование вынесено в отдельную функцию:

```dart
Future<(List<ClassNode>, List<ClassRelation>, int)> _scanInIsolate(
  String path,
) {
  return Isolate.run(() => ProjectScanner().scanProject(path));
}
```

Важно, что замыкание создаётся **вне обработчика события**: иначе оно захватит
`ProjectBloc`, `emit` и другие непересылаемые объекты, и изолят упадёт с ошибкой
`Illegal argument in isolate message`.

Что это даёт:

- файловый обход и разбор AST не блокируют UI;
- окно не «замерзает» на больших проектах;
- между изолятами передаётся только путь и простые данные
  (строки, списки моделей), поэтому новый `ProjectScanner` создаётся внутри изолята.

## 7. Парсеры (паттерн «Стратегия»)

Интерфейс: `lib/services/parsers/language_parser.dart`.

```dart
abstract class LanguageParser {
  String get languageName;
  bool canParse(String filePath);
  Future<List<ClassNode>> extractClasses(File file);
  Future<List<ClassRelation>> extractRelations(
    File file,
    Set<String> knownClassNames,
  );
}
```

`ProjectScanner` хранит список парсеров и выбирает первый, который подходит по расширению.

Каждый парсер также сохраняет номер строки объявления класса в `ClassNode.line`
(для перехода в VS Code).

| Парсер | Файлы | Как ищет классы | Как ищет связи |
|---|---|---|---|
| `DartParser` | `.dart` | AST через `analyzer` (`parseString`, `ClassDeclaration`) | `extends`, `implements`, `with` + типы полей класса |
| `PythonParser` | `.py` | RegExp `^\s*class Имя(...)` | родительские классы в скобках + type hints (`переменная: Класс`) |
| `CSharpParser` | `.cs` | RegExp `class` / `interface` с модификаторами | базовые классы после `:` + объявления полей |

Дополнительно парсеры определяют абстрактные типы:

- Dart — ключевое слово `abstract`;
- Python — базовый класс `ABC` или `ABCMeta`;
- C# — модификатор `abstract` или объявление `interface`.

### 7.1. DartParser

Использует настоящий AST, поэтому устойчив к форматированию и комментариям.

- `extends` → `superclass.name.lexeme`
- `implements` → все интерфейсы
- `with` → все миксины
- поля: `FieldDeclaration` → тип поля
- все найденные имена проверяются через `knownClassNames`

### 7.2. PythonParser

- класс ищется регулярным выражением, привязанным к началу строки (`^`);
- родители берутся из скобок: `class User(Repository, Serializable):`;
- модульные префиксы отсекаются: `types.User` → `User`;
- использование ищется по type hints: `repo: UserRepository`.

### 7.3. CSharpParser

- учитывает модификаторы `public/private/protected/internal`, `static/abstract/sealed/partial`;
- распознаёт и `class`, и `interface`; интерфейс считается абстрактным типом;
- родители берутся после `:` и разделяются запятыми;
- дженерики и namespace отсекаются: `List<MyClass>` → `List`, `System.Web.Client` → `Client`;
- использование ищется по объявлениям вида `MyClass field;` или `MyClass field {`.

Во всех трёх парсерах регулярные выражения привязаны к началу строки,
поэтому однострочные комментарии (`// class Foo`, `# class Foo`) классами не считаются.

## 8. Аналитика и аномалии

Всё считается в обработчике `AnalyzeProject` в `lib/blocs/project_bloc.dart`.

### 8.1. God Object (аномалия)

1. Для каждого класса собирается множество **разных** классов, которые его
   используют (`usage`). Повторные связи одного класса считаются один раз:

```dart
usageSources[rel.toClassId].add(rel.fromClassId);
```

2. Если класс используют **больше 5 разных классов** (6 и больше) — он попадает
   в `allAnomalyNodeIds` (все найденные аномалии). Наследование не считается.

3. Из этого набора вычитаются аномалии, которые пользователь признал
   допустимыми. Оставшиеся попадают в `anomalyNodeIds` и считаются активными.

### 8.2. Исключение аномалии («так и задумано»)

Иногда God Object — осознанное решение архитектора. На вкладке «Аномалии»
у каждого класса есть кнопка **«Не аномалия»**:

- класс перестаёт быть красным на графе;
- не учитывается в счётчике активных аномалий;
- не уменьшает Health Score;
- ИИ-помощник больше не выдаёт для него предупреждение;
- класс переходит в блок «Исключённые из анализа», откуда его можно
  вернуть кнопкой **«Вернуть»**.

Выбор сохраняется отдельно для каждого проекта:

```
ключ shared_preferences: ignored_anomalies:<полный путь к проекту>
значение: JSON-массив ID классов
```

Поэтому после перезапуска приложения и повторного открытия того же проекта
все исключения восстанавливаются. Если проект удалить из истории, его настройки
исключённых аномалий остаются в хранилище (не мешают другим проектам).

### 8.3. Изолированные классы

Собираются все ID, которые участвуют хотя бы в одной связи (`fromClassId` или `toClassId`).
Все остальные классы считаются изолированными и попадают в `isolatedNodeIds`.

### 8.4. Здоровье проекта

```
Health = 100 - min(активные аномалии × 5, 35)
             - round(доля изолированных × 20)
```

- каждая активная аномалия снимает 5 баллов, но не больше 35 суммарно;
- изолированные классы штрафуются по их доле в проекте (не больше 20),
  поэтому в большом проекте пара изолированных классов почти не влияет;
- исключённые пользователем аномалии **не штрафуются**;
- результат не может быть меньше 0;
- цвет в UI:
  - `>= 80` — зелёный;
  - `>= 50` — оранжевый;
  - `< 50` — красный.

### 8.5. Ограничение графа

- `graphNodes` только применяет фильтр «Скрывать изолированные».
- Сам граф (`GraphViewWidget`) рисует не более **400** классов за раз.
- Если классов больше, сначала показываются аномалии, исключённые аномалии
  и абстракции, затем — самые связанные обычные классы.
- В шапке графа выводится «Показаны 400 из N классов», поэтому большой проект
  больше не превращается в пустой экран.
- Раскладка идёт секциями: «Аномалии», «Исключённые аномалии», «Абстракции»,
  «Обычные классы». Это визуальная фильтрация по типу сущности.

## 10. Экран анализа (`AnalysisPage`)

Файл: `lib/pages/analysis_page.dart`.

При создании страницы создаётся `ProjectBloc` и сразу отправляется событие:

```dart
ProjectBloc()..add(AnalyzeProject(widget.projectPath))
```

Экран состоит из трёх панелей.

### 10.1. Левая панель — навигация и статистика

Ширина 275 px. Содержит:

- **Граф связей** — вернуться к графу;
- **Структура классов** — открыть дерево наследования;
- **Файлы (N)** — открыть вкладку со списком файлов;
- **Здоровье: X/100** — открыть детальный отчёт;
- **Аномалии (N)** — открыть список God Objects;
- **Связи (N)** и **Классы (N)** — справочная статистика;
- **Switch «Скрывать изолированные»** — фильтр мёртвых классов.

Активный пункт выделяется фоном, жирным шрифтом и цветной иконкой.
Клик отправляет `SelectSection`.

Панель можно свернуть и развернуть кликом по вертикальной полосе-ручке
(`_PanelHandle`). Такая же ручка есть у правой панели.

### 10.2. Центральная панель — контент по разделам

В зависимости от `state.section` показывается:

| Раздел | Виджет | Что показывает |
|---|---|---|
| `graph` | `GraphViewWidget` | Интерактивный граф |
| `structure` | `StructureView` | Дерево наследования и реализации |
| `files` | `FilesView` | Файлы проекта |
| `health` | `HealthView` | Детальный отчёт о здоровье |
| `anomalies` | `AnomaliesView` | Активные и исключённые аномалии |

Если идёт загрузка — спиннер. Если ошибка — сообщение об ошибке.

### 10.3. Правая панель — карточка класса

Ширина 320 px. Если класс не выбран — подсказка «Нажмите на класс на графе…».

Если выбран:

- имя класса;
- язык (Dart / Python / C#);
- путь к файлу (максимум 3 строки, с `ellipsis`);
- бейджи `abstract`, `наследников: N`, `наследует: Родитель`;
- красный баннер, если это активная аномалия;
- зелёный баннер, если аномалия исключена пользователем;
- **блок ИИ-помощника**;
- «Использует (N):» — исходящие связи (зелёная стрелка справа);
- «Используют его (N):» — входящие связи (голубая стрелка справа).

Вся карточка обёрнута в `SingleChildScrollView`, чтобы не было переполнения.

### 10.4. Граф (`GraphViewWidget`)

Файл: `lib/widgets/graph_view_widget.dart`.

- обёрнут в `InteractiveViewer` (зум и перетаскивание);
- используется **собственный layout**, без пакета `graphview`;
- классы разложены секциями по типу:
  - **Аномалии** — красные;
  - **Исключённые аномалии** — тёмно-зелёные с галочкой;
  - **Абстракции** — оранжевые, с иконкой и подписью `abstract`;
  - **Обычные классы** — нейтральные серые;
- узел: прямоугольник 164×68 с именем и языком;
- **выбранный класс** сохраняет цвет типа, но получает толстую жёлтую рамку,
  свечение и значок `my_location`;
- при выборе класса показываются только его связи, в двух цветах:
  - **голубые** — классы, которые используют выбранный или наследуют его
    (входящие связи), и стрелки от них к выбранному;
  - **зелёные** — классы, которые выбранный использует или наследует
    (исходящие связи), и стрелки от выбранного к ним;
  - если класс связан с выбранным в обе стороны, его заливка становится
    градиентом голубой → зелёный;
- у связанных классов появляется свечение в цвет направления, поэтому
  связь видно даже на тёмном фоне;
- без выбранного класса рёбра скрыты, поэтому граф не засоряется;
- сверху — короткая легенда: роли классов, а при выборе — жёлтая рамка
  и два направления связей;
- если классов больше 400, выводится баннер «Показаны 400 из N классов»;
- клик по узлу отправляет `SelectNode`.

> Собственный layout заменил `graphview`, потому что пакет на больших графах
> мог не построить дочерние элементы (пустой граф) и оставлял «висящие»
> зависимости при выходе со страницы — отсюда была ошибка
> `'_dependents.isEmpty': is not true`.

### 10.5. Вкладка «Структура»

Файл: `lib/widgets/analysis_views.dart`, класс `StructureView`.

- строит деревья наследования через `state.hierarchyGroups`;
- для каждого корня показывает имя, язык, номер строки, бейдж `abstract`
  и количество потомков;
- потомки выводятся с отступом по глубине;
- отдельный блок «Без наследования» содержит все классы, не попавшие
  ни в одно дерево (в виде чипов);
- у каждого класса есть кнопка **↗ «Открыть в VS Code»** (и клик по чипу).
  `EditorService` открывает файл на нужной строке: сначала через `code -g`,
  затем через `open -a "Visual Studio Code"`, затем через URL-схему `vscode://`;
- если VS Code не найден, показывается `SnackBar` с подсказкой.

### 10.6. Вкладка «Аномалии»: исключение

- Активные аномалии показываются с красной рамкой и кнопкой **«Не аномалия»**.
- Исключённые — в отдельном блоке с зелёной иконкой и кнопкой **«Вернуть»**.
- Клик по карточке выбирает класс и возвращает к графу.
- Настройки сохраняются per-project (см. п. 8.2).

## 11. Реализованные задачи

### Задача 1. Оживление навигации

- Добавлен `enum AnalysisSection { graph, structure, files, health, anomalies }`.
- Добавлено событие `SelectSection`.
- Центральная панель переключается через `switch (state.section)`.
- **Структура:** `StructureView` строит деревья наследования и позволяет
  открыть класс в VS Code.
- **Файлы:** `FilesView` группирует классы по `filePath`, показывает имя файла,
  полный путь и количество классов. Сверху есть поиск **только по имени файла**
  (путь не учитывается): запрос хранится в состоянии (`filesQuery`), фильтрация —
  в `filteredClassesByFile`.
- **Здоровье:** `HealthView` показывает оценку, цветной прогресс-бар и построчный
  расчёт: база, штраф за аномалии, штраф за изолированные классы, итог.
- **Аномалии:** `AnomaliesView` выводит список God Objects с количеством входящих
  зависимостей. Клик по аномалии выбирает класс и возвращает к графу.

### Задача 2. Интерактивный граф и правая панель

- Связи в правой панели обёрнуты в `InkWell`.
- Клик по связи отправляет `SelectNode(target)` и `SelectSection(graph)`:
  граф выделяет класс жёлтой рамкой, карточка обновляется.
- В левую панель добавлен `SwitchListTile` «Скрывать изолированные».
- Он отправляет `ToggleHideIsolated`; фильтрация выполняется в `graphNodes`,
  а цвета оставшихся классов не меняются.

### Задача 3. ИИ-помощник (локальная экспертная система)

Метод `ProjectLoaded.aiAdviceFor(node)` проверяет условия по порядку:

| Условие | Совет |
|---|---|
| Класс в `anomalyNodeIds` | ⚠️ «Этот класс слишком сильно связан с другими. Рекомендуется применить паттерн Фасад или разделить его на несколько классов.» |
| Класс в `isolatedNodeIds` | 💤 «Этот класс не имеет связей. Возможно, это мертвый код или точка входа.» |
| Есть исходящая связь типа `inheritance` | 🧬 «Этот класс расширяет другой класс. Убедитесь, что не нарушается принцип подстановки Барбары Лисков.» |
| Иначе | ✅ «Класс выглядит архитектурно чистым. Количество связей в норме.» |

Совет показывается в правой панели сразу при выборе класса. API и интернет не используются.

- **Управление аномалиями.** На вкладке «Аномалии» можно исключить класс
  («Не аномалия») или вернуть его. Решение сохраняется per-project в
  `shared_preferences` и не влияет на другие проекты.

## 12. Хранение истории проектов

Файл: `lib/services/storage_service.dart`.

- Ключ в `shared_preferences`: `recent_projects`.
- Значение — JSON-массив объектов `RecentProject` (у каждого только `path`).
- `getRecentProjects()` — читает и восстанавливает список.
- `addRecentProject(project)`:
  - удаляет старую запись с таким же путём;
  - вставляет новую в начало;
  - оставляет максимум 10 записей.
- `removeRecentProject(path)` — удаляет запись по пути.

Исключённые аномалии хранятся отдельно:

- ключ: `ignored_anomalies:<путь к проекту>`;
- значение: JSON-массив ID классов;
- `getIgnoredAnomalies(projectPath)` — читает набор для проекта;
- `saveIgnoredAnomalies(projectPath, ids)` — сохраняет набор.

## 14. Полный путь работы приложения

1. Запуск → `main.dart` → `WelcomePage`.
2. `WelcomePage` загружает из `shared_preferences` список путей к проектам.
3. Пользователь нажимает «Открыть проект» → системный диалог выбора папки.
4. Сохраняется только путь, открывается `AnalysisPage` (или пользователь кликает
   по «ранее открытому» — проект сканируется заново).
5. `ProjectBloc` получает `AnalyzeProject(path)`.
6. BLoC загружает исключённые аномалии для этого пути, затем `Isolate.run`
   запускает `ProjectScanner.scanProject`.
7. Сканер обходит файлы, парсеры находят классы (проход 1) и связи (проход 2),
   определяют абстрактные классы и интерфейсы.
8. BLoC считает все аномалии, активные аномалии, изолированные классы и Health Score.
9. Публикуется `ProjectLoaded`.
10. UI строит статистику, граф, структуру и правую панель.
11. Клик по узлу → `SelectNode` → узел получает жёлтую рамку, его входящие
    и исходящие связи окрашиваются в два разных цвета, карточка и совет ИИ
    обновляются.
12. Клик по связи справа → выбор класса + переход к графу.
13. Переключатель → `ToggleHideIsolated` → граф перестраивается без изолированных.
14. Левая навигация → `SelectSection` → граф / структура / файлы / здоровье / аномалии.
15. На вкладке «Аномалии» кнопка «Не аномалия» → `ToggleAnomalyIgnored` →
    решение сохраняется для проекта, здоровье пересчитывается.
16. «Экспорт» → формирование текста → `FilePicker.saveFile` → файл на компьютере.

## 16. Ограничения и возможные улучшения

### Ограничения текущей версии

- Анализ только на уровне классов, без методов и вызовов функций.
- Python и C# разбираются регулярными выражениями, а не полноценным AST:
  возможны ложные срабатывания в сложном синтаксисе.
- Одинаковые имена классов в разных файлах могут перекрывать друг друга
  в словаре `имя → ID`.
- Учитываются только связи `inheritance` и `usage`; импорты не анализируются.
- При множественном наследовании/реализации интерфейсов дерево строится по
  **первому** родителю; остальные родители видны в списке связей.
- Абстрактность Python определяется по базовому классу `ABC`/`ABCMeta`,
  а не по наличию `@abstractmethod`.
- «ИИ-помощник» — это набор правил, а не языковая модель.
- На графе одновременно отрисовывается не более 400 классов
  (остальные не теряются в данных, но не рисуются).
- Граф использует собственный layout, поэтому это не классическая
  Sugiyama-раскладка, а сгруппированные секции по типу классов.
- Открытие в VS Code работает, если редактор установлен; в GUI-приложении
  macOS команда `code` может быть недоступна в PATH — тогда используется
  стандартный путь установки или `open -a "Visual Studio Code"`.
- Нет базы данных и сохранения результатов анализа между запусками
  (сохраняются только история путей и исключённые аномалии).
- На macOS sandbox отключён, чтобы повторно читать папки из истории;
  это осознанный компромисс для локального инструмента.

### Куда можно развивать

- Полноценный AST для Python и C# (или LSP).
- Поиск и фильтрация по имени класса, языку, файлу.
- Автоматическое центрирование графа на выбранном узле.
- Экспорт в JSON/PDF и добавление даты/версии проекта.
- Кэширование результатов сканирования.
- Подключение реальной LLM для более глубоких рекомендаций.
- Метрики: связанность (coupling), связность (cohesion), циклы зависимостей.
